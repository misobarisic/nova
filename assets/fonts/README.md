# Bundled UI fonts

`Roboto-Regular.ttf` and `Roboto-Bold.ttf` are the hinted static faces from
[googlefonts/roboto-2](https://github.com/googlefonts/roboto-2/tree/38062f4b4a0be4346d07a928408da21602545e9e/src/hinted),
revision `38062f4b4a0be4346d07a928408da21602545e9e`. Both use the Apache-2.0
license in `LICENSE.txt`, included in Nova's in-app license catalog.

`crates/ui/appwindow.slint` imports both faces and sets Roboto as the window's
default family. `crates/ui/build.rs` embeds them for packaged builds on every
platform. Regular covers body text; bold covers the UI's 600/700 emphasis through
font weight matching. Linux live preview loads the same imports from the
checkout. System fallback still supplies scripts absent from Roboto.

`NotoColorEmoji.ttf` contains the **full** 2D COLRv1 vector font from
[googlefonts/noto-emoji](https://github.com/googlefonts/noto-emoji/tree/e20cbc2bbec1926686be9f9bee7d1d2cfa1fea0e/2D/fonts),
revision `e20cbc2bbec1926686be9f9bee7d1d2cfa1fea0e`, with a compatibility
patch generated by `tools/prepare_emoji.py`. It uses OFL-1.1 in
`NotoColorEmoji-LICENSE.txt`; no reserved font name is declared there.
No upstream vector glyphs are removed. The patch restores the previous bitmap
font's 1,612 legacy ligature aliases and blank NUL/CR mappings, retaining their
scaled advances. Each alias points to the vector glyph of an equivalent
canonical sequence; the original artwork is not copied from the bitmap font.

| Font | Bytes | SHA-256 |
| --- | ---: | --- |
| Original full `NotoColorEmoji.ttf` (CBDT/CBLC bitmap) | 10,730,124 | `15671215ab769fdc7162a045d56fd7d7e477c51b04e6b3c761d914d8fdd6cc44` |
| Upstream full `Noto-COLRv1.ttf` | 5,038,236 | `b8e25ea68db82f9e4d0aee921f4420be2be39887bd5c893a2ad98710531f9d0c` |
| Packaged COLRv1 with compatibility aliases | 5,060,792 | `08745abde9e5d4c52fc9f7e852338872328b87113d2b87b385e3ab27b0aa196c` |

The packaged font saves 5,669,332 bytes (52.8%) before package compression.
With the same ordinary Linux `release` profile, the full executable decreased
from 139,867,144 to 134,375,816 bytes: a net saving of 5,491,328 bytes (3.93%),
including the new desktop painter and source notices. This does not measure
Android APK or distribution-package compression.
This is a format replacement, not a character subset. Upstream's vector file
has 1,508 cmap entries and 42,330 glyphs; the compatibility patch restores the
baseline's full 1,510-entry cmap and retains all vector glyphs plus two empty
control glyphs. `emoji-coverage.txt` records all 4,176 directly Unicode-mapped
GSUB ligature inputs from the bitmap baseline, including legacy reversed
sequences. Its alias rows also name their canonical equivalent. The generator
checks cmap inclusion and HarfBuzz shaping for every sequence, then verifies
alias glyph identity. `crates/ui/src/fonts.rs` additionally exercises all of
those sequences through Slint's shaper with the emoji family selected and no
system fonts, plus representative production fallback cases. Parley's existing
Roboto-first fallback splits keycaps across fonts because Roboto covers their
ASCII bases; both the old bitmap and new vector face show that limitation.
Explicitly selecting the emoji family shapes the complete repertoire in both.
Codepoint and sequence coverage do not imply pixel-identical bitmap/vector artwork.

To regenerate (Python 3, with `fonttools==4.67.0` and `uharfbuzz==0.56.3` installed):

```sh
python assets/fonts/tools/prepare_emoji.py
python assets/fonts/tools/prepare_emoji.py --check
```

Both upstream inputs are downloaded from the immutable revision and verified
by SHA-256. `--inputs DIR` uses previously downloaded inputs instead. The bitmap
font remains an input only; it is not shipped or retained in this repository.

The font and license ship in every packaged build. `crates/ui/src/fonts.rs`
registers the embedded font and appends it to Slint's generic fallback chains
before showing the window. This covers flag pairs and joined emoji without
relying on the desktop or Android system font inventory; Roboto stays the
primary text family. Merely importing/registering the emoji family does not
add it to those fallback chains. Desktop uses the local FemtoVG 0.27 COLRv1
painter (skrifa 0.44, tiny-skia 0.12); Android keeps Slint 1.18's Skia renderer.
The configured Android skia-bindings 0.153.3 FreeType build contains native
COLRv1 traversal and paint support. Physical-device color validation is still
required; shaping coverage alone does not verify rendering.

An optimized CPU-only comparison on a Ryzen 5 5500U sampled 12 emoji at
16/32/64 px. It compared Swash's PNG bitmap decode/scale path with the current
COLRv1 painter, using warm metadata but bypassing the glyph atlas (20 warmups,
seven alternating passes of 1,000 iterations; median per path). Median costs
across the 12 samples were:

| Size | Bitmap | COLRv1 |
| --- | ---: | ---: |
| 16 px | 253 µs | 118 µs |
| 32 px | 350 µs | 187 µs |
| 64 px | 445 µs | 357 µs |

Complexity matters: Croatia's detailed flag took 2.45/3.63/5.56 ms as a vector,
versus 0.25/0.35/0.46 ms as a bitmap. Including it, the equal-weight sample means
were higher for COLRv1 at every size, despite vectors being faster in 26 of 36
individual cases. These are one laptop's uncached CPU measurements, not
Android timings or frame-rate results. Both formats use the same GPU glyph
atlas; cached redraws skip decoding/rasterization.

Android's mpv subtitle setup also uses the regular face; see
`crates/player/src/lib.rs`.
