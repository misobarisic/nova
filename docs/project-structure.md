# nova — Project Structure

> Orientation map for AI agents and new contributors. Read this first instead of
> crawling the tree: it explains what every crate/module is for, how data flows,
> where state is persisted, and which files to open for a given task.

`nova` is a cross-platform (Linux and Windows desktop + Android) media catalog / player app in
the style of Stremio. It talks to Stremio-protocol addons over HTTP and loads explicitly installed
sandboxed JavaScript ZIP packages. AniKoto and Supernova sources live in the
separate `nova-addons` checkout; no provider or default repository is bundled. It plays direct URLs with an
in-window **mpv** player and can stream torrents through an embedded BitTorrent
client. A recent feature adds **cross-device sync** over
[iroh](https://iroh.computer) (the `iroh` branch).

- Language: Rust 2024, UI in [Slint](https://slint.dev) 1.18
- Root package `nova`; heavy subsystems split into leaf crates under `crates/`
- Two entry points: desktop `src/main.rs`, Android `android_main` in `src/lib.rs`; both call `app::run()`

## 1. Quick start

```sh
# Dev shell (Nix) — provides Rust, Slint, mpv, native dependencies, and Linux cargo-sweep
nix develop              # Linux desktop toolchain
nix develop .#android    # + NDK/SDK/JDK/cargo-apk2
nix develop .#windows    # MinGW cross-build tools + pinned libmpv

# Build / check
cargo check              # whole workspace (desktop default features)
cargo build              # desktop binary: target/debug/nova
cargo build --profile cd-release # tagged distribution profile: target/cd-release/nova
cargo run                # run desktop app
cargo dev                # retained live-preview alias; currently compiled UI with a warning

# Make targets (enter `nix develop` or `nix develop .#android` first)
make linux-run
make linux-run-preview
make linux-run-release
make android-build
make android-build-release
make android-build-release ANDROID_TARGET=armv7-linux-androideabi
make android-build-release-universal
# Tagged CI uses fat LTO; local Make release targets accept the same profile:
make android-build-release-universal RELEASE_PROFILE=cd-release
make android-run
make android-run-release
# For an emulator: append ANDROID_TARGET=x86_64-linux-android

# Tests
cargo test                              # root app unit + integration tests
cargo test --workspace                  # also leaf-crate unit + documentation tests
cargo test -p nova-sync --lib            # sync crate unit tests (fast)
cargo test --test ui_settings_sync -- sync_overflow:: # headless Slint UI regression tests
cargo test --test ui_discover --test ui_library --test ui_player # isolated UI suites
python3 -B -m unittest discover -s .github/scripts -p test_package_android.py

# Android Make rules use cargo-apk2 (not cargo-apk): it compiles android/java/
# to DEX and declares the foreground service + sync job. They enable the
# Android Slint backend with `--features android`; enter `nix develop .#android`
# before invoking them. Make targets never enter Nix shells themselves.

# Windows x86_64 check (cross-build from Linux)
cargo check --workspace --locked --target x86_64-pc-windows-gnu
```

Pull requests and source/build changes pushed to `main` run Linux formatting,
Clippy and workspace checks, the shared OpenGL state guard regression on Linux,
and Windows GNU and ARM64 Android target checks. `check-android` uses the
Android Nix shell with `--no-default-features --features android --lib -p nova`
and `--target aarch64-linux-android`.
Pushing a Git tag selects the `cd-release` Cargo profile through the workflow's
`NOVA_RELEASE_PROFILE`, building four Android APKs, a Linux
x86_64 `.deb` and AppImage, and a Windows x86_64 ZIP, then attaches all seven
files to a GitHub Release. Android release filenames are
`Nova-Android-arm64-v8a-<version>.apk`, `Nova-Android-armeabi-v7a-<version>.apk`,
`Nova-Android-x86_64-<version>.apk`, and `Nova-Android-universal-<version>.apk`
(version is the tag without its leading `v`, with `/` replaced by `-`).
The universal APK contains all three architectures; ARMv7 supports devices
running a 32-bit ARM Android userspace, including compatible TV devices.
The Windows bundle is named `Nova-Windows-x86_64-<version>.zip` (tag without
the leading `v`, with `/` replaced by `-`). `.github/scripts/package-windows.sh`
places the executable, DLLs, and license/source notices directly inside it.
The Actions upload uses `archive: false`, so downloading the build artifact
returns that ZIP directly. The release job downloads it by artifact ID with
`skip-decompress: true` to preserve the ZIP for publishing. Linux release
files are named `nova-x86_64-<tag>.deb` and
`nova-x86_64-<tag>.AppImage`; both come from one native Ubuntu 22.04 build.
The `.deb` declares shared-library dependencies, while the AppImage bundles
libraries using linuxdeploy. Nova uses Slint's Winit/FemtoVG backend; Qt is
not required.

Windows keeps its native title bar and caption buttons; a Winit window-attribute
hook in `src/app/run.rs` requests the dark native frame before creation.
Context menus use Slint-rendered popups instead of Win32/muda
(`SLINT_NO_MUDA`, set before service/window initialization in `src/app/run.rs`).
`crates/ui/build-support.rs::compiler_configuration` selects `fluent-dark`
for every Windows UI compilation unit using Cargo's target OS, including
Linux cross-builds, so menus remain dark even with a light Windows system theme.
Other targets retain their existing widget style and menu presentation.

The Android workflow invokes cargo-apk2 once to build all three architectures into
a universal APK. `.github/scripts/package-android.py` derives the three
architecture-specific APKs from that output, aligns and signs all four with
the same selected-profile key cargo-apk2 uses (environment override, then Cargo metadata),
and checks signatures, signing certificates, exact ABI sets, native libraries,
and unchanged payload bytes/compression. All four APKs share one Actions
artifact for the release job to collect. `.github/scripts/test_package_android.py`
checks ABI coverage against Cargo's targets, split payloads, native library
completeness and corruption rejection using temporary APK fixtures; the Linux
CI check runs it without Android tooling.
Packagers read the selected profile directory explicitly: `target/cd-release`
for Linux and the universal APK, and `target/x86_64-pc-windows-gnu/cd-release`
for Windows. Outside CI, `NOVA_RELEASE_PROFILE` defaults to `release` in these
scripts, and Make's `RELEASE_PROFILE` also defaults to `release`. Android signing
for `cd-release` uses `CARGO_APK_CD_RELEASE_KEYSTORE` and
`CARGO_APK_CD_RELEASE_KEYSTORE_PASSWORD` when set, otherwise the matching Cargo
metadata entry; the tracked key retains update compatibility for authorized
personal builds, while store releases require a private key override.

Cargo aliases live in `.cargo/config.toml`. Android linkers come from the
`.#android` dev shell env vars (see `.cargo/config.toml` comments); that shell
also provides `cargo-apk2` (packaged by the flake) and unsets `CPATH` (the
stdenv's host include path, which the NDK clang would otherwise pick up).
Target-specific `BINDGEN_EXTRA_CLANG_ARGS_*` also pass the NDK sysroot and API
26 target to host libclang when generating Android bindings.
The Android shell supplies Rust standard libraries for ARM64, ARMv7 and x86_64;
the matching pinned `full` mpv libraries and checksums live under
`vendor/android-libs/` (see `SOURCES`).
`nova-player` enables `libmpv2-sys/use-bindgen` on 32-bit Android so the mpv
bindings use target-correct layouts instead of upstream's 64-bit assertions.
ARMv7 builds compile Skia from source because upstream's prebuilt Android
artifacts cover ARM64/x86_64 only. The shell supplies Python, GN, Ninja, Git, curl
and the NDK path required by this fallback; tagged builds allow extra time.

The workspace's `dev` profile disables debug information and strips symbols;
the default `test` profile inherits these settings. Incremental compilation
remains enabled. This reduces linked executable size while making development
and test backtraces less detailed. Release and `dev-release` also strip symbols.
The `cd-release` profile inherits `release` (optimization level 3 and stripped
symbols), enables fat LTO, uses one codegen unit and disables incremental
compilation. Tagged Android/Linux/Windows builds use it; ordinary local release
builds retain their current compilation settings.

The 27 generated UI leaf libraries and the type-only `nova-playback-api` library declare `[lib] test = false` to skip empty
unit-test harnesses during default workspace test selection. Their normal
libraries still build for the app and root UI integration suites; the main
`nova-ui` library keeps its seven real unit tests. Explicit `--lib` or
`--all-targets` selection can still request the empty harnesses. Documentation
tests remain enabled separately. Plain root `cargo test` and targeted
`--test ui_*` commands already exclude leaf-library unit harnesses.

**Features** (root `Cargo.toml`):
- `desktop` (default): enables Slint's Winit/FemtoVG backend, the pinned FemtoVG fork’s COLRv1 glyph painter, and `unstable-winit-030` window access for native player cursor visibility.
- `android`: enables Slint's Android Activity backend (Skia on Android);
  Android builds use `--no-default-features --features android`.
- `live-preview`: retained opt-in development feature, currently compiled UI with a build warning. The page factories need native compiled globals/handles; interpreter hot reload requires a separate bridge.

subject first, then the purpose where useful (`library-behavior.md`,
`metadata-pipeline.md`, `sync-hardening-plan.md`). Use `follow-ons` consistently
for deferred work. Keep repository-level conventions such as `README.md` and
`AGENTS.md` unchanged, and update links when renaming a document.

### Crate dependency graph

```
                                 ┌─────────────┐
                                 │ nova (root) │  binary + lib (cdylib/rlib for Android)
                                 └──────┬──────┘
  ┌──────────────┬──────────────┬───────┼──────┬──────────────┬──────────────┐
  ▼              ▼              ▼              ▼              ▼              ▼
  nova-ui        nova-player    nova-media     nova-download  nova-torrent   nova-sync    addons
  │              │              │              │              │
  slint,         nova-config,   nova-config,   serde,         nova-config,   (standalone)
  nova-config,   nova-ui,       slint,         tokio,         nova-storage,
                 slint          addons,        reqwest        iroh,tokio
  nova-ui-{settings,home,discover,calendar,detail,library,more,player-osd,onboarding}
  nova-ui-shared                image,webp

                                                              │
                                                              nova-storage (redb)
```

`nova` and `nova-sync` also depend on the small `nova-playback-api` contract crate
(Serde only); the native player stays independent of the networking transport.
`nova` and `nova-media` also depend on `nova-providers`, which depends on
`addons`, `reqwest` (blocking HTTPS), `scraper`, `quick-xml` (bounded feeds), and `rquickjs`/QuickJS. Android
enables QuickJS's `bindgen` feature; the Android Nix shell supplies libclang
and target-specific NDK sysroot arguments.
`nova` also depends on `nova-tracking`, which depends on `nova-storage`, Serde, reqwest, URL parsing and zeroized credentials;
the tracking actor owns local state, shared plaintext credentials and authenticated delivery. Chrono supplies local calendar dates; `getrandom` supplies OAuth state/PKCE entropy. Android tracker HTTPS uses a preconfigured rustls client with bundled Mozilla roots, matching the other Android HTTP clients and avoiding the platform verifier's JNI/Kotlin runtime requirements.

## 3. Root crate `nova` (`src/`)

### Entry points
- `src/main.rs` — desktop `main`; installs jemalloc on Linux, selects the GUI subsystem on Windows so launches do not open a console, and calls `nova::app::run()`.
- `src/lib.rs` — re-exports leaf crates under stable paths (`crate::storage`, `crate::player`, `crate::torrent`, `crate::download`, `crate::net`, `nova_ui::*`), declares `pub mod app`, and holds `android_main` (Slint Android backend init + `app::run()`).
- `src/diagnostics.rs` — initializes the process-wide `tracing-subscriber` once without replacing an embedding subscriber. `RUST_LOG` filters events (default `warn,nova_sync=info`; `RUST_LOG=nova_sync=debug` enables sync diagnostics). Desktop writes to stderr; Android writes directly to logcat under `Nova`, including job-only startup. Sync leaf code emits structured events/spans through `tracing`; it does not install a subscriber.

### `src/app.rs` — the spine
Defines the shared state and the UI bridge:
- **`Shared`** (`Arc<Mutex<Shared>>`): all app state — installed addons, type/catalog defs, current catalog + `MetaPreview`s, library `entries`, `progress`, home `continue_list`/`home_history_list`/`new_episodes_list`/`upcoming_list`, modal/stream state, cache settings, per-title playback preference records and pending edits, detail snapshots, and transient Calendar/Downloads artwork identities/retention state. UI callbacks lock this.
- **`Bridge`** (`Clone`): `slint::Weak<AppWindow>` + `Arc<Mutex<Shared>>` + `catalog_gen` + desktop poster pipeline + `player` + `DownloadCoordinator` + synced `last_stream::Cache` with a local file mirror. Every UI-mutating method runs on the main thread.
- Data model types: `Installed`, `CatDef`, `TypeDef`, `StreamSource`, `PendingStream`, `StreamUi`, `ModalItem`, `DetailSnapshot`, `EpisodeProgress` / `PlaybackHistory`, `PlaybackTarget`, `ContinueEntry`, `UpcomingEntry`, `LibraryEntry`, `AddonStore`, `WatchStatus`, `ViewingPhase` / `ViewingActivity` (`watch_state.rs`), `MetaHeader`, `CacheSettings` (from config).
- Poster pipeline: dual-priority `hi`/`lo` request channels and worker pool; image/cache ownership lives in `nova-media::cache`, while the app keeps request and UI publication state. Detail episode/season jobs use unique job-ID registrations and a shared four-slot pump; `page_artwork.rs` owns the separate four-worker Calendar/Downloads queue.
- Declares the `app` submodules (below) and re-exports their `pub(crate)` items.

### Threading model (important)
- **All Slint property/callback access is main-thread only.** `Bridge` methods are called from UI callbacks on the main thread.
- Background work (HTTP, decode, torrent, sync) runs on worker threads or tokio runtimes and hops back with `slint::invoke_from_event_loop(...)`.
- Installed JavaScript packages run in a fresh QuickJS runtime on the fetch worker. The runtime bounds memory, stack, execution time, response size, redirects, request count, and domain-scoped HTTPS. Its host APIs provide GET/permission-gated POST, three-way GET batches (including `batchEach` completion callbacks on the invoking QuickJS thread), per-request soft timeouts within a shared operation budget, CSS and safe XML selection, bounded v1 torrent inspection, session storage, durable scoped settings/cache, redacted logging, and encoding helpers. Resolver selections run on workers with the existing playback request token, addon revision and settings generation; Android suspension cancels pending resolution. HTTP bodies, redirect origins and public DNS addresses are checked before requests. The optional manifest `limits.scriptTimeMs` defaults to 5 seconds and is capped at 10 seconds; Supernova uses 10 seconds for matching/metadata/sorting while AniKoto retains 5 seconds. The overall operation deadline still applies. Only actual blocked time on the invoking thread is excluded from the script-processing budget; concurrent IO never credits executing callbacks. `nova.streams.publish` sends bounded replacement snapshots during stream lookups; registry validation matches the final response before `nova-media::net::fetch_bytes_with_progress` forwards them to the app. Ordinary remote addons remain final-only.
- HTTP text and binary responses have separate representations (`body` vs `bodyBase64`), avoiding duplicate large buffers. Installed provider warnings use bounded `novaWarnings` alongside ordinary stream rows; typed resolver errors never expose upstream response bodies. Credential-bearing final playback links require manifest-declared HTTPS CDN/path/query permissions. The host derives `novaSensitivePlayback`, and `PlaybackIntent`/`nova-player::play_with_preferences_and_policy` retain in-app-only playback through resume prompts and Android decoder recovery; links are never persisted or synced.
- Supernova currently declares `domains: ["*"]` for HTTP and final playback, allowing all public domains. Other providers retain scoped domain lists. HTTPS/public DNS/private-address checks, operation limits and authenticated redirect restrictions remain enforced independently of this wildcard.
- Supernova adds opt-in Nyaa, AnimeTosho, Knaben v2, StremThru and The Pirate Bay / APIBay sources; the clearer Pirate Bay label preserves the stored `sources.apibay` preference. Knaben uses its public GET API and bounded advertised pagination, ignoring untrusted download proxies in favor of hash-verified metainfo. StremThru ports Comet's Torznab inventory query through a configurable public HTTPS URL, using an IMDb ID when available and the official title/year/category fallback otherwise; safe upstream labels retain `StremThru|Knaben` provenance. The Nyaa/AnimeTosho adapters port Comet's broad title discovery and request/parsing patterns, following advertised pagination up to six canonical-title pages and two episode-query pages, with an AnimeTosho JSON fallback. `matching.js` separates numeric title suffixes from episode ranges and admits compatible season inventories only for exact-file inspection. A 20-second lookup and 48-request ceiling retain at most 300 ranked candidates per wave, while visible results stay capped at 50. Configurable priorities use only cached availability, parsed resolution, bytes, season-pack labels and reported seeders; missing values stay last, stable row IDs break ties, and every combined TorBox/P2P snapshot sorts before the display cap. The existing preferred quality still biases the bounded discovery/inspection pool. First-page TorBox availability publishes before deeper discovery; subsequent waves check only new hashes, and better later releases may replace earlier candidates. Native three-way completion callbacks publish cumulative cached rows and then verified P2P rows without waiting for every request. Cache-hit metainfo retries retain the original discovery expiry; failed empty searches are not retained. Exact-context nonempty, warning-free lists also persist in the OS cache directory for up to 15 minutes (`nova.cache.get/set`), bounded by the original discovery expiry; lists with pending P2P file inspections bypass this cache so retries can proceed. Reopens, including after restart, avoid HTTP while TorBox selection still resolves afresh. Each TorBox availability batch proves and renders each candidate once rather than repeating that work for cumulative snapshots. Unverified candidates and direct torrents when P2P is disabled are omitted without status messages in the stream picker. Shared release evidence enriches language/codec/resolution ranking and presentation from Nyaa descriptions, optional APIBay details, Knaben descriptions and StremThru descriptions/media attributes; AnimeTosho retains native Nyaa references only for enabled-source detail fetching. The generic parser recognizes labelled inventories, tables and MediaInfo, ignores prose/categories/links/comments, and leaves conflicting scalar claims unknown. Source-owned detail IDs and matching returned hashes bind fetched descriptions to a release; at most six 1-second optional GETs share the 48-request cap and 2.2-second wave deadlines. Normalized detail facts persist in the OS cache for 24 hours, misses for 60 seconds; normalized evidence/references may accompany existing durable discovery rows, but raw descriptions do not persist. Selected-file probes override release-level hints per field, and metadata upgrades retain stable row IDs. Existing identity/file verification remains unchanged.
- `nova-providers::registry` adapts installed JS packages to existing Stremio catalog/detail responses at `nova-provider://<provider-id>`, deriving descriptors from manifests. Startup restores explicitly installed packages without registering defaults; legacy bundled-provider markers are retained but no longer read. ZIP updates preserve existing membership, enabled state and order. AniKoto keeps its existing URL and `anikoto:` media/episode IDs. JS owns site parsing, related-entry discovery, and fresh-token playback extraction; Rust's `metadata.rs` and `sequence.rs` own reusable enrichment, canonical candidate selection, and episode alignment. A bounded `nova.metadata.checkpoint` preserves fetched native details if optional discovery times out. Metadata capability calls require `permissions.addonMetadata`; contextual lookup is declared by `capabilities.contextualStreams`.
- Metadata enrichment resolves explicit IMDb/TMDB/MAL/AniList connections before searching enabled, available installed addon catalogs through ordinary catalog/meta endpoints; already connected addons skip speculative title searches. Blank native fields permit fallback, and display fields are selected only after conflicting connections are removed. Later confirmed providers can fill missing episode artwork/text while the first accepted mapping keeps its display numbering; duplicate aliases retain independent provenance until conflict filtering and final deduplication. Cinemeta participates in general enrichment only as an enabled installed addon. Official v3 Cinemeta series responses, including metadata candidates used to enrich bundled sources, also get a bounded, optional live-endpoint artwork repair (`metadata/cinemeta.rs`): only one-to-one normalized-title matches within the same IMDb series and matching special/regular classification can replace Metahub URLs; globally unique titles tolerate missing/differing dates, while repeated titles require a unique match within one calendar day, leaving IDs, numbering and other metadata intact; confirmed corrections survive failed/malformed/unrelated/partial refreshes. `nova-media` injects the bounded transport; immutable snapshots keep workers away from app locks. A nested guard and visited requests prevent recursion. Optional enrichment has a five-second deadline, 32 requests, 100 previews per search response, six detail candidates, and 2 MiB response cap. Nested providers inherit the remaining deadline; Android transport retains preconfigured rustls. See [metadata fetching and reliability](metadata-pipeline.md) for the complete pipeline, cache policies and remaining gaps.
- `SourceSequence` describes native titles/aliases/year, season/part labels, declared counts, and available stable episode IDs. The shared Rust mapper supports separate/split/merged seasons and cours, unequal parts, continuous numbering and unique-title anchors, rejecting gaps/ambiguity/conflicts. Explicit later-season titles also align standalone season-1 numbering when complete regular counts and absolute numbering prove the single-season layout. Opened AniKoto entries are included even if absent from search and reuse fetched rows. Two globally unique positional title anchors plus equal counts can confirm shortened series names without conflicting anchors. Show connections never imply episode aliases by themselves.
- `detail.rs::{source_stream_lookup,episode_stream_ids,stream_endpoint_owned}` routes contextual streams through provider capabilities and confirmed aliases through recipient manifest restrictions, without AniKoto-specific app branches. Private IDs remain owner-scoped; non-global aliases additionally require addon provenance. Confirmed external fields enrich native entries; ordinary main-series numbering and established saved episode IDs remain stable through coverage reconciliation. Standalone/bundled entries retain native availability. Library/history/download/sync identities and fresh-token resolution are unchanged. `novaExternalIds` retains typed show claims; `novaStreamIds`, opaque `novaConnections`, `novaMetadataRevision`, and `novaSourceUrl` retain aliases and ownership in existing JSON episode metadata caches. Conflicting claims suppress aliases; inventory revisions invalidate obsolete cached routes across addon changes/restarts. Fresh aliases update pickers and restart stream searches; `stream_generation` rejects stale replies and selected captions/thumbnails refresh without disturbing playback.
- Host enrichment caches use `metadata:v2:<digest>` in bounded session storage shared with JS (2 MiB total; 256 KiB host entry cap, 16 KiB JS entry cap). Confirmed mappings/artwork (including direct Cinemeta thumbnail corrections) also persist locally in `provider_metadata_cache:v1` through `metadata/cache.rs` and `src/app/io.rs` (128 entries, 8 MiB total). Complete confirmed results are reused for 30 days, while incomplete episode fields refresh on the next fetch after five minutes; failed refreshes retain prior confirmed results for the same fingerprint, while explicit conflicts invalidate them. Missing/ambiguous results stay session-only for 30 seconds. Native sequence/availability, artwork matcher version and canonicalized addon inventory revisions are part of the key, preserving restart reuse while invalidating changed inputs. Oversized results remain usable uncached. AniKoto's direct MP4/HLS, MegaPlay and Mewcdn resolution, headers/subtitles, in-app playback, and MP4 download forwarding remain in their existing paths; finite HLS downloads use the shared offline-bundle worker. Image-wrapped MegaPlay segments remain unsupported. See `crates/providers/README.md` for the JS service contracts.
- `nova-media::net` uses a **fire-and-continue** API: callers pass a continuation, never block or spawn threads.
- Remote sync callbacks (`set_on_remote`, `set_pair_callback`) arrive on the tokio runtime thread and are marshalled to the UI thread in `start_sync` (`sync.rs`). Playback protocol callbacks follow the same rule through `remote_playback.rs::attach_playback_service`; only the UI thread inspects snapshots, checks the live session and dispatches player commands.
- HTTP and provider-addon HLS downloads share the same queue. `crates/download/src/hls.rs` chooses the highest-bandwidth non-I-frame variant and retains its audio/subtitle groups, segment boundaries, initialization maps, byte ranges, discontinuities and ordinary AES-128 keys. Provider headers accompany every request. HTTP 429 responses retry up to six times through the shared HTTP worker, honoring seconds/date-form `Retry-After` or using exponential backoff when absent/invalid. Cooldowns are cancellable and bounded to five minutes total per request; a longer server deadline fails rather than retrying early. Header timeouts apply to each attempt, including initial and nested playlists, segments, maps and keys; committed segments remain reusable. Live playlists and unsupported encryption fail explicitly; DASH and website-only YouTube links remain unsupported. Each job stores a local `.m3u8` entry plus an `hls/` subdirectory in its existing `downloads/http/<job-id>/` directory. Segment completion markers verify source URL and byte length before resume reuse; incomplete segments restart. HLS reports actual downloaded bytes plus a stable resource-completion percentage for the label, rail and Android notification; it never alternates an estimated byte total with an unknown one. Resource counts are transient (`serde(skip)`) and reconstructed on resume. The entry is published only after all assets are complete, so orphan adoption cannot mistake individual segments for finished episodes. Automatic watched cleanup retains the actively playing HLS episode until player-close finalization so its remaining segments stay available; manual removal still deletes immediately. Removing an episode download (including auto-delete-watched) recursively removes the entire job directory, keys, subtitles, markers and partial files included; active removals cancel first and clean up when the worker exits. No new KV schema is needed.
- Stream downloads use the `nova-download` worker/queue; progress is read by the 250 ms UI tick, so no Slint access occurs on transfer threads. The tick refreshes the pinned download rows **in place** (`set_row_data`) when the row set/order is unchanged, instead of replacing the whole `streams` model: replacing the model destroys every row delegate, including the Android hold-to-open action-sheet timer, which then never fires while a transfer is active. The same tick reaps a transfer worker that ended without finalizing (panic/unwind), so a dead worker cannot pin the single active slot and stall every queued download.
- Deferred provider streams can be downloaded through the same queue. Each attempt resolves a fresh link on a worker and verifies the installed owner/settings revision; navigation retains the captured episode. Only `nova-resolver:stream-<stable hash>` markers persist in `downloads:v1`; resolver tokens, signed links and headers stay in memory. Private HTTP transfers omit resume sidecars and validators, restart partial files on retry, sanitize transport errors, and reject HLS before writing playlists. Incomplete jobs require reselecting Download after restart; completed files remain available offline. Ordinary HTTP/HLS and torrent resume behavior is unchanged.
- New HTTP jobs persist a fixed-length SHA-256 artifact path before transfer, independently of readable `title`/`display`/`file_name` labels. This reserves room for `.part.resume.json` even with long Unicode source names. Valid legacy paths and completed files remain usable; oversized legacy partial/validator pairs migrate on the worker without overwriting existing resumed files, using a streaming copy when hard links are unavailable. Cleanup still owns the complete job directory.

### Translations (i18n)

- **User-facing strings are marked with `@tr("…")`** in the `.slint` files. The whole interface is covered; string *values* that reach the UI as data (addon names, stream labels, disk sizes) stay untranslated. Mark new strings as you add them — Slint falls back to the source text when a catalog has no entry, so marking is always safe.
- **Counts that inflect use Slint's plural form**: `@tr("{n} episode" | "{n} episodes" % count)` (the syntax is `"singular" | "plural" % n`, extra `{}` args follow). The `hr` catalog carries the three Croatian forms and the header's `Plural-Forms` selects them.
- `build.rs` points `slint-build` at `translations/`, so the gettext catalogs are compiled into the binary at build time (domain = `CARGO_PKG_NAME` = `nova-ui`, i.e. `translations/<code>/LC_MESSAGES/nova-ui.po`). The directory must hold at least one catalog. `translations/en/` registers English and includes explicit source-language entries; English is the source language, and missing entries fall back to the source text.
- `compile_page_library` reads the same source catalogs directly, setting the compiler patch's `SLINT_BUNDLE_TRANSLATIONS_DOMAIN` override to `nova-ui` while preserving each library's package identity. No catalogs are copied into watched build outputs. All units bundle the same language list/order and use context-free entries; Slint's shared language selection therefore indexes each unit consistently. Edit only `crates/ui/translations/`.
- **Catalogs are context-free**: `build.rs` sets `DefaultTranslationContext::None`, so an entry is keyed by the source string alone. Slint's default context is the *component* a string sits in, which would silently unmatch an entry when a `@tr` literal moves to another component. Regenerate/verify catalogs with `slint-tr-extractor --no-default-translation-context`; a string that means two different things in two places can still name a context (`@tr("ctx" => "…")`).
- **Text the Rust backend formats goes through `crates/ui/src/backend_text.rs`** (download states, sync status, stream/episode hints, relative air dates, count labels). Fixed strings are keyed by the English source (`text::tr("Queued")`); templated text uses named helpers, plus Croatian 1/2-4/5+ noun forms. This API is owned by `nova-ui` alongside the Slint UI and translation catalogs. `Bridge::apply_language` updates it and refreshes already-materialized Rust text in visible models (library badges/category labels, Home rows, detail rows, Discover hints, and Settings status).
- **Stored identifiers are never translated, only their labels.** The automatic library buckets (`Plan to Watch`, `Watching`, …) and the `WatchStatus` labels are *keys*: the filter comparison, `activity_bucket` and the persisted values use the English identifier, while the UI shows a localized label — `library.rs` pushes `category_names` (values) plus `category_labels` (display); Library’s filter pills render the latter while callbacks report the stored value. Watch-status pills are translated at the two display sites (`text::tr(badge_label())`).
- **Languages**: English (source) and Croatian (`hr`, `crates/ui/translations/hr/…` + backend helpers in `crates/ui/src/backend_text.rs`). Croatian addresses the user in the formal plural ("vi"); labels stay short, which the Croatian-width phases in `addons/addon_row_fit.rs` / `settings_sync/sync_overflow.rs` enforce (a longer label overflowed a 320px phone row, and one unwrapped card heading widened the whole Sync subpage).
- Switching language selects Slint's bundled catalog with `slint::select_bundled_translation(code)` in `src/app/i18n.rs`, which marks every `@tr` binding dirty. Rust-built strings are values rather than bindings, so the bridge separately refreshes localized model text from existing state without refetching content or rebuilding poster pipelines. `"en"` restores the source strings. The chosen language is Settings → Display → Language (`nova_config::Language`), synced by default with optional per-device overrides.
- Adding a language: catalog directory + a `Language` variant (`ALL`/`index`/`code`/`label` arms in `crates/config/src/lib.rs`; the picker list is built from `ALL`, so the row follows automatically) + backend translations/helpers in `crates/ui/src/backend_text.rs`. Untranslated strings stay English.
- The retained `cargo dev` / `live-preview` feature currently uses AOT generation too, so bundled translations work as in ordinary builds. Interpreter hot reload is deferred until its dynamic globals and page attachment can use an appropriate bridge.

## 5. Persistence

### Primary store: redb (`nova-storage`)
Single database at `<data_dir>/nova.redb`, table `kv` (`&str → &str`). Open once
via `nova_storage::init_at(dir)` before any read/write. The `try_*` APIs distinguish
missing keys from database/transaction failures; legacy convenience wrappers
report failures through `last_error`. Unreadable app snapshots are write-blocked,
and Settings displays a persistence warning. The typed `local_sequences_v1` table
(`&str → u64`) holds device-local monotonic counters, separate from JSON KV values
and synced records. `playback:boot_epoch:v1` reserves a boot epoch atomically
before the playback transport starts; its initial value is `1 << 63` to exceed
normal epochs from older wall-clock-based clients. Later allocations increment
the committed value, and storage/schema/exhaustion failures stop setup rather
than reusing an epoch. Keys used by the app:

`home_rows` (ordered `HomeRow` entries: a tagged `HomeRowSource` identifying
Continue Watching, Watch history, New episodes, Upcoming, or an addon catalog, plus an enabled flag). Fresh installs enable all four built-ins in that order. Addon
identity stores install URL, media type, catalog ID and optional genre. A missing
or null `home_rows` lazily migrates legacy `home_row_sources`,
`home_continue_enabled` and `home_upcoming_enabled`; an explicit empty list means
no landing catalogs. Missing legacy visibility flags default to enabled; explicit
disabled, reordered or removed rows remain unchanged. Layout edits write both the new list and legacy compatibility
fields. Disabled addon selections keep their local cached metadata. Selections
survive unavailable/removed manifests, and the list syncs as one settings field;
no sync wire schema changes are required.

Local metadata keys (`episodes:*`, `meta_header:*`, `manifest:*`,
`provider_metadata_cache:v1`, legacy `plugin_cache:v1` (migrated out at startup), `home:showcase:v1`, `tracking:catalog_cache:v1`)
use `metadata_cache_v1` in the same database. The logical format remains JSON.
`crates/storage/src/codec.rs` wraps values with an envelope version, codec and
uncompressed length; zstd level 3 with a checksum is used from 1 KiB when the
complete encoded value saves at least 10%. Small/unprofitable values stay raw
inside the envelope. Decoding bounds output and frame windows to 64 MiB; larger
writes retain legacy plain storage. Existing `kv` rows remain readable and move
atomically on their next metadata write. `home:catalog-rows:v1` currently remains
plain JSON because it is absent from the app's metadata compression policy.
Library and progress (plus `sync:baseline:library` / `sync:baseline:progress`)
use registered collections in `state_rows_v1`; settings, credentials and sync
record rows remain in `kv`. Compression does not alter sync wire formats,
metadata refresh policy or image files, and does not shrink existing database
allocation immediately. Equal JSON values (ignoring object key order) skip
writes; timestamps, array order and unknown fields still count as changes.

Helpers: `src/app/io.rs` (`read_json`/`write_json`), and per-domain
`read/write_persisted_*` functions. `nova-storage` exposes `write_batch`
(single transaction for many rows) and `scan_prefix` (ordered prefix scan),
which the sync store uses to persist per-record rows without rewriting a blob.
Synced app snapshots, baselines, dirty rows, and HLC commit in one batch through
`sync.rs::persist_sync_snapshot` and `nova_sync::prepare_snapshot`. Dirty work is
retained until commit succeeds. Settings enum recovery is field-isolated and
preserves unsupported raw values until that field is deliberately edited.

`collections.rs` keeps a versioned `__nova_rows_v1` descriptor (kind, count and
revision) under each collection's original `kv` key. Physical keys include the
collection-name byte length followed by the collection name and item identity;
array records carry stable ranks to preserve saved Library order. Deletions and
appends retain surviving ranks/bytes; deliberate reorders renumber them. `try_get_str`
and prefix scans rebuild the same logical JSON for callers. Legacy plain JSON
migrates on its next write in the same transaction as the sync records,
baselines, journal and HLC. Only changed rows are encoded/written; removed rows
are deleted. Small/unprofitable records stay raw, and oversized records retain
plain UTF-8 rather than exceeding the compressed codec's bound. Corrupt rows,
missing rows or invalid order fail closed and prevent replacement; explicit
collection removal still deletes corrupt payloads. The collection table is
authoritative user data and is never treated as a disposable metadata cache.
Older binaries cannot read this storage layout: the descriptor intentionally
fails their typed snapshot/baseline parsing. Downgrading requires a compatible
reader or restoring a pre-migration backup, not deleting the descriptor.

`src/app/persistence.rs` moves normal Library/history serialization, diffing,
compression and atomic writes to one ordered worker. App helpers expose the
newest queued snapshot, while the worker derives activity/journal transitions
from committed state. Adjacent periodic progress saves may coalesce; manual
edits retain ordering. Failed heads stay queued for retry, and errors reach the
existing Settings persistence warning. The queue applies backpressure at 64
pending snapshots. Pause/completion/close, Android backgrounding and orderly
shutdown flush; other synchronous snapshot writes and remote sync exchanges
drain the queue before taking the record-owner lock. Stremio materialization
queues record-sized external patches alongside local snapshots, recreating both
`ApplyingGuard` and external-origin guards on the writer; its actor awaits the
durable receipt off-thread. Queued logical readers overlay these patches in
order. Other remote projection remains synchronous under `ApplyingGuard` so
projection receipts follow durable saves. `Store::clock` exposes a cheap HLC
observation token for optimistic UI delivery without copying a full digest.
Diffing and logical reads still traverse collections; this avoids whole-blob
recompression and disk rewriting, not all linear in-memory work. No wire
schema/ALPN change or new compression setting is introduced.

### Legacy files
Legacy desktop `settings.toml`, `library.toml`, and `addons.toml` files are no
longer imported. Current settings, library entries, and addons are read only
from the KV store in `<data>/nova.redb`; any old files are left untouched.

### Paths (`nova-config`)
- Platform data and cache paths are listed in [platform-storage.md](platform-storage.md).
- Addon ZIP archives live under `<data>/addons/packages/<lowercase-sha256>.zip`; `src/app/addon_packages.rs` validates immutable content and registers only desired descriptors.
- Downloaded media lives under `<data>/downloads/` (private and durable; HTTP jobs use per-job `.part` files with `.part.resume.json` representation validators and torrent jobs use a retained subdirectory).
- `NOVA_DATA_DIR` / `NOVA_CACHE_DIR` are Android test/device-farm fallbacks.
- Linux and macOS use XDG roots; the platform-specific path helper honors custom
  `XDG_DATA_HOME` and `XDG_CACHE_HOME` values only when absolute; empty/relative roots fall back to HOME, then the temporary directory.

### Image cache (`nova-media::cache`)
The byte-budgeted decoded LRU and disk cache share a key made from source URL
and the resolved processing recipe, so consumers with identical recipes share
decoded entries. Each disk variant is one atomic `.variant` file: `NVIMAGE2`
magic, a length-prefixed JSON header, then processed encoded bytes. The
versioned header stores source URL, registered uses, dimensions, resolved
recipe and a checksum of the encoded payload. No separate metadata/use files or
original-image backup are retained. Source pixels are transient and are
resized before Slint receives them. Compression uses JPEG or WebP at the
selected quality, with PNG fallback for alpha that JPEG cannot preserve;
resizing without compression writes PNG, while Original with compression off
keeps source bytes. Disk caching off is a pure in-memory mode. Same-recipe fetches coalesce,
and a fresh download is encoded and decoded at the recipe's quality before
publication, matching disk content. Atomic writes preserve the prior valid
variant on failure. A recipe change fetches the source again and never upscales
an existing processed variant. Per-URL locks serialize disk changes. Legacy
`.img`/`.cfg` files are invalidated only after a successful replacement;
startup does not sweep them. Cache clear advances a generation, and loads also
capture the image-settings revision; stale work cannot repopulate cleared cache
state or publish pixels for superseded settings. Per-recipe publication tickets
order overlapping ordinary loads, forced refreshes and maintenance snapshots:
an older completion cannot replace a newer successful source in disk, memory
or delivery, even if the newer pixels were evicted or exceed the LRU budget.
Tickets retain completion pixels only while an older load or refresh needs the
newer result; queued maintenance snapshots retain ordering metadata only. The
decoded LRU remains the sole retained pixel cache. Maintenance also watches
its use-registration snapshot, including settings changes away and back, and
skips registrations rebuilt by a newer load. Disk envelope/storage schemas are
unchanged.
`cache_gc.rs` tracks successful disk publications and memory/disk hits in a
single `.image-usage-v1.json` index beside the images. Hits only update memory;
dirty recency batches every two minutes and never rewrite variant payloads.
An orderly shutdown flushes a clean marker; missing/corrupt/unclean indexes
rebuild from bounded headers. Daily reconciliation and orphan-temp cleanup are
gated by local DB timestamps supplied by `src/app/cache_gc.rs`; cheap checks and
Android resume do not themselves scan. Workers yield after 128 files or about
20 ms and pause when disk caching is off. Going over the configured limit uses
the index immediately to evict toward 90% of the cap. Invalid variants go first,
then older browsing artwork, then Library artwork if needed. Library preference
is soft, not unlimited retention. Recent accesses and active publications defer
eviction; existing maintenance/generation/per-URL guards protect clear,
re-encode and load races. Screenshots and downloads are outside this cache.

The memory budget counts decoded pixels owned by this cache. Visible Slint
images, crossfading artwork, transient processing buffers and GPU allocations
remain outside it; it is not a limit on total process memory.

The re-encode action snapshots settings, fetches each registered source URL
once, rebuilds its registered uses under current recipes, and supports cancel
or per-entry failure. It may download those sources again. Clear cache removes
all variant files and usage metadata. Resolution dropdowns offer Original and
240, 360, 480, 720, 960, 1024, 1280, 1920 or 2560 pixels; changes autosave
immediately and work with disk caching or compression disabled. Home keeps its
existing original-resolution showcase/backdrop and logo behavior, with 480px
cards. Four resolution preferences extend the existing settings JSON; no sync
domains or wire schemas were added.

## 6. Cross-device sync (`crates/sync` + `src/app/sync.rs`)

The most intricate subsystem. Sync is **opt-in** (`sync:settings.enabled`);
nothing binds a socket until `SyncEngine::setup()` runs.

Correctness and recovery work is tracked in
[`sync-hardening-plan.md`](sync-hardening-plan.md) (implemented contracts, regression matrix, and remaining device/power validation).

### Design
- Generic, app-agnostic store: `domain -> key -> Record { value, version }`.
- `Version` = HLC (`physical_ms`, `counter`) + `dev` id + `deleted` flag; LWW merge with tombstones. See `merge.rs`, `hlc.rs`, `store.rs`.
- Socket-free `local_store` owns records even with networking disabled. Fresh untouched settings seed only a baseline; explicit settings edits publish intent even when selecting the default. Legacy persisted settings conservatively seed absent keys. Receive/reload reject or quarantine clocks beyond the one-hour drift bound.
- Progress values carry JSON activity/watch/unwatch action registers (`__nova_progress_v1`), merged by deterministic action version. Watch stays sticky unless superseded by explicit unwatch; rewinds use the activity register, position/duration stay coherent, and play count takes max. Legacy values initialize registers from their record version.
- Anti-entropy: each peer exchanges a **per-domain hash** of its version map, then full version maps only for domains that differ, then just the records the other lacks or has stale. One bidirectional QUIC stream per exchange (`protocol.rs`); an unchanged domain transfers no digest at all.
- **Connection reuse:** the dialer keeps one connection per peer and opens a fresh bi stream per pass; the accept handler serves streams for the connection's lifetime. A closed/failed connection is evicted and redialed (`lib.rs`).
- **Local change scheduling:** `crates/sync/src/lib.rs` batches ordinary successful edits for 2 seconds with a 10-second maximum; periodic playback checkpoints use a fixed 120-second automatic window. `prepare_snapshot` reports actual record mutations, so no-op writes and remote projections do not schedule echoes. Pause, completion, close and episode replacement save progress then immediately flush pending changes once through the existing worker, preserving peer backoff. Ordinary automatic edits wait while backgrounded; Android Pause checkpoints through the app bridge before UI timers suspend and allows one live-owner handoff pass. Periodic sync remains unchanged and may transmit playback earlier. No new settings, persisted fields or protocol changes.
- **Recovery/cadence:** periodic wakes honor monotonic per-peer backoff; explicit `sync_now` and completed network refreshes reset backoff for one bounded, coalesced pass. Overlapping network refreshes coalesce, and recovery wakes only after iroh refresh finishes. Interval/foreground changes recompute the pending periodic deadline immediately (`lib.rs`).
- Sync frames are **postcard** inside a codec byte with optional **zstd level 3** (`frame.rs`, shared zstd dependency); pairing and removal keep raw postcard. postcard is non-self-describing, so schema changes require an ALPN bump. Current ALPNs:
  - `nova/sync/3` (`ALPN`) — record exchange (per-domain digest hashes + compressed frames). During testing the compressed codec changed from DEFLATE (1) to zstd (2) without an ALPN bump; old compressed frames are rejected and both devices must update. Bodies from 256 bytes compress only when smaller; output and decoder windows are capped at 32 MiB. Encoders disclose the known postcard length to reduce small-frame workspace; declared oversized content is rejected before decompression.
  - `nova/pair/2` (`PAIR_ALPN`) — invite-ticket pairing
  - `nova/remove/1` (`REMOVE_ALPN`) — one-shot "you were removed" notice
  - `nova/party/2` (`nova-party::ALPN`) — independent lazy endpoint/router, not the sync endpoint. Version-2 `NVP2` expiring capability invites bind temporary guests to authenticated endpoint identities; only bounded media identity, clock/timeline and readiness frames are shared. No record sync, pairing or addon transfer is registered; no guest becomes a sync peer.
  - `nova/playback/2` (`PLAYBACK_ALPN`) — separate ephemeral playback requests/snapshots on the existing paired endpoint, with bounded 256 KiB postcard frames, peer membership checks, connection reuse, request-ID replay protection and revocation of queued work. It does not enter record anti-entropy or persisted sync state.
  - `nova/addon-package/1` (`PACKAGE_ALPN`) — raw content-addressed ZIP transfer, capped at 8 MiB, separate from record exchange. Paired membership is checked before and during transfer; cancellation and engine shutdown interrupt pending work.

Live playback uses `nova-playback-api::{Request, Response, PlaybackAction}` rather
than sync records. The UI-thread coordinator rejects stale session commands,
keeps local playback and remote control mutually exclusive through loading,
and sends receiver-owned stream selections as opaque offers. Active control
snapshots are requested from the 250 ms UI tick (at most 4 Hz, with one request
in flight, alongside a separate stream lookup so controls remain responsive); paired-device summaries refresh every five seconds only while
Home, Devices or the stream selector is visible. Foreground readiness is
required; Android background jobs do not install a playback handler. Screenshot
commands save on the playing device using its existing screenshot preferences.
Receiver addons are queried concurrently and merged in installed order; lookup replies
carry up to 256 opaque offers, including receiver-computed display sizes, with
25-row selector paging. The controller keeps at most 32 per-peer display-only lookup results for the current selector, reusing matching media for under five minutes from lookup start when toggling output devices. Close, refresh, Start, expired entries, peer removal, or engine replacement invalidate reuse; receiver source/revision checks still apply. Offers expire after five
minutes, are checked against addon/settings revisions, and keep sources local. A lookup retains its original settings generation through addon batching and rejects stale batches before publishing offers.
Cached and fetched episode metadata use the same resolver: exact native IDs take
precedence; otherwise only a unique current confirmed alias is accepted. Cached
aliases can therefore resolve receiver downloads without a live metadata addon.
Interactive commands follow normal receiver persistence and sync notifications;
controller snapshots never apply local progress or preference writes.
Detaching retires the controller connection without stopping receiver playback;
queued requests and held-speed cleanup remain bound to that connection so a
reopened controller cannot inherit stale input. Continuous control updates coalesce
only with a matching queue tail, preserving intervening relative/reset commands.
Receiver resolver failures retain a failed session until Stop closes the error
overlay; snapshots report a generic failure without forwarding provider errors.
Requester boot epochs come from the durable local sequence allocator, preserving
stale-process rejection across restarts even when the system clock moves back.
The ordered epoch field is unchanged. Playback protocol v2 adds the receiver's
formatted size (bounded to 32 bytes) to each offer; the controller uses that value
for stream size pills. Both playback participants must support v2; ordinary sync
ALPNs remain unchanged.

### Domains (app side, `src/app/sync.rs`)
`library`, `progress`, `addons` (one record per addon URL plus a whole-value
LWW `order` record listing installed URLs, so reorder syncs mesh-wide), `addon_packages` (one `{id, version, sha256}` desired package descriptor per provider ID; raw archives transfer separately),
`last_stream` (one `selection` record containing only version, fingerprint and original selection time; LWW selection, seven-day expiry and guarded expiry tombstones),
`settings`, `plugin_settings` (independent plugin/field values including unknown fields and explicit tombstones; no wire schema/ALPN change), `category` (per-name union), `continue_hidden` (one record per Home
item the user removed, value = removal unix secs; tombstones carry the
"un-remove" when a resume or prune drops the key, and a stamp written while sync
was off is kept and published like `progress`), `watch_history_hidden` (one removal timestamp per typed title; existing generic string domains need no wire schema or ALPN change), plus
`tracking` (version-1 typed source/account/release links, automatic pauses and
shared sign-in tokens; projected by the tracking actor with local cursors and
atomic credential/link saves), `stremio` (shared version-1 auth-only `connection`, including plaintext auth key and explicit sign-in epoch; only browser auth replaces it and disconnect tombstones it. `session:<JSON(epoch)>:automatic` is an independent boolean LWW preference; `...:started` and `...:bootstrap` are monotonic true-only markers. Independently timestamped `event:<JSON(account,type,native ID)>:<field>` and `title:<JSON(account,remote ID)>:<field>` rows retain source and merged actions; fields are `saved`, `resume`, or `watched:<JSON episode ID>`; `title:<JSON(account,remote ID)>:remote` stores the acknowledged server `_mtime` and canonical clocks as a JSON tuple, reusing original action times only when the server revision and field values match), `peers` (mesh membership) and `presence`
(engine-owned sightings, see below).
`sync_records` compares against the materialized baseline, not the live store;
only baseline keys absent from the edited snapshot become tombstones. New domains ride the existing
record exchange with no wire-schema change (domain names travel as strings);
the app ignores unknown domains, so old peers stay compatible.

### Peers / membership model
- The `peers` domain holds one record per peer endpoint id: value `{name, added_at}`; deletion = tombstone.
- The **live allowlist** (`SyncEngine.peers`) is derived from the store (`reconcile_peers`) and is the trust boundary (`Handler::is_peer`).
- **Additions** happen only via explicit pairing / manual add (`peers_add`, may resurrect a tombstoned peer). A routine sync only refreshes an existing live peer's name (`peers_refresh`) and never inserts/resurrects.
- **Removals** are tombstones (`peers_remove`). Removal is made symmetric:
  - `SyncEngine::remove_peer` sends a best-effort `nova/remove/1` notice so the removed device drops the remover and shows a UI notice.
  - If the notice is missed, a structured QUIC application-close code (`REVOKED_CODE`) triggers mutual removal. An unknown/not-yet-authorized peer does not get that code. Authorization is rechecked for every stream and under the store lock before apply; cached dialed connections close on removal.
- **Stale third-party tombstones** are ignored: if `sync:peer_acks[X]` is newer than a tombstone's HLC, `apply_frames` keeps `X` (a peer you actively sync with survives someone else's removal).
- **Presence (last-seen):** the engine-owned `presence` domain holds one record per `{observer}\x01{peer}` sighting (value = unix secs), written after each completed exchange and throttled to one rewrite per 15 min per peer. Each device writes only its own observer keys (no merge conflicts); readers take the max across observers plus the local ack clock (`SyncEngine::peer_last_seen`, shown as `SyncPeer.last_seen`). `peers_remove` tombstones sightings involving the removed peer.
- **Self-records** are never applied (you never add yourself). A tombstone keyed by your own id sets a "removed us" signal.
- **Tombstone GC** is gated by per-peer acks (`ack_floor`): a tombstone is only reclaimed once every current peer has acked past it (30-day TTL floor).

### App wiring
- Startup establishes/migrates baselines and replays only pending projection receipts before deriving Library/Home models, independently of networking. Stores without projection metadata require one migration replay. `sync_apply` publishes progress-derived models once per batch. Desktop defers sync/torrent creation and download queue start until the first completed render; engine construction runs on workers. `Bridge::start_sync` attaches callbacks, replays any records received during setup and requests a pass; a generation guard prevents a completed desktop setup from reinstalling sync after disable. Android retains foreground/background lease startup.
- `sync_apply` reads the socket-free owner; thread-local, nesting-safe `ApplyingGuard` suppresses echo writes. Deferred addon callbacks retain origin and generation, while desired order/flags are read at completion. `settings_edited(field)` preserves explicit default choices; `persistence_failed` exposes storage health through AppWindow and SettingsPage.
- Durable apply marks pending domains before callback delivery. `Done` and valid stream completion are required for success/ack; writer tasks abort on every cancellation path, including joining. Pairing commits invite consumption and trust together, and the joiner installs trust before closing its completion connection.
- Pairing UI: Settings → Sync (`ui-settings-sync/sync-module.slint`), invite create/join, confirmation prompt with match code. The created ticket is also rendered as a QR image (`qr.rs`); on Android the invite card offers a camera scanner (`android_qr.rs` + `android/java/dev/misob/nova/QrScanActivity.java`) that decodes a ticket and joins automatically.

## 8. Testing

- **Addon package backend**: `src/app/addon_packages.rs` runs its real worker/event-loop installer in an isolated child process to verify updates, rejected imports, state preservation, archive repair, and cancellation after removal.

## 9. Conventions & gotchas

- **No comments policy is not absolute here** — this codebase is heavily
  commented with rationale. Match the surrounding style; explain *why*, not *what*.
- **Leaf-crate split is deliberate**: editing app logic should not recompile
  heavy deps (Slint codegen, mpv, iroh, librqbit, redb). Keep new heavy
  subsystems in their own crate.
- **postcard wire schemas are not self-describing**: adding/reordering fields in
  `crates/sync` wire structs requires an ALPN version bump (sync is `/3`;
  pairing/removal are unchanged by sync-frame compression). Local storage stays
  JSON, but the sync store is one row per record, not a single blob.
- **Row heights follow wrapped text, not line estimates**: Slint measures
  wrapped `Text` at its intrinsic width during the preferred-height pass, so
  rows that reserve a fixed/estimated height clip on narrow screens. Rows use a
  hidden zero-height measurement copy at the live width (`SettingsRow`, the
  detail stream list) to size themselves; keep that pattern when adding rows
  with variable text.
- **Slint API changes are three-step**: page component + `AppWindow` property/callback + `run.rs` wiring. Missing a step is a common compile/runtime error.
- **New user-facing strings are marked `@tr("…")`** (the `nova-ui` catalogs bundle at build time; see §4). The catalog is English-only today, so marking changes nothing on screen — it is what makes a later language possible. Translation *values* pushed as data (language names, sizes, statuses) stay untranslated.
- **UI thread only** for Slint; use `slint::invoke_from_event_loop` from workers.
- **Android player keyboard/D-pad order** (open note): the centered transport
  keeps the logical keyboard indices (play = 1, rewind = 3, forward = 4) while
  reading 3 → 1 → 4 left-to-right on screen. Left/right traversal (`kb_prev` /
  `kb_next` in `player.slint`) skips the removed volume slot (2) and the narrow
  track buttons (5/6), but does not reorder to mirror the visual layout. Remap
  those helpers if exact on-screen D-pad order is ever wanted.
- **`ScrollView` needs a direct layout child to scroll**: its content size is
  derived from direct layout children only, and a bare `if`-conditional child
  is ignored — the viewport then collapses to its own height and touch drag
  silently does nothing. Wrap view-gated content in an unconditional
  `VerticalLayout` (see `home.slint`'s subpage grid) like Library/Settings do.
- **`ScrollView` content is at least viewport-tall**: the compiler binds
  `content-height = max(flickable.height, layout.min-height)`, so a short page
  still fills the viewport and its unpinned rows/cards absorb the slack
  (`vertical-stretch` defaults to 1) and stretch. Settings subpages keep their
  content top-aligned by pinning the fixed rows (`vertical-stretch: 0`) and
  ending the scroll content with a `Rectangle { vertical-stretch: 1; }` spacer
  that absorbs the excess; long content still scrolls.
- **Page-level overlays are siblings of the page layout, never layout children**: a `MenuSheet` (or any full-page overlay) declared *inside* the page's `VerticalLayout` is laid out as a row — opening it then squeezes/pushes the page content instead of covering it, which looks like "everything got pushed to the top" (most visible on Android). Declare it as a direct child of the page root `Rectangle`, after the layout, as the Library, Detail and Home sheets do.
- **Nested `Flickable`s do not axis-lock**: the page sees the press first and
  holds it for its drag-vs-tap delay. Home uses the Detail stream-pill pattern:
  its interactive inner rails use Slint's drag and native inertia, while each
  card's `TouchArea` reports early touch moves (`touch-finger-id` is nonzero
  before the held-back press). A horizontal hint disables page panning; a
  vertical gesture or release hands it back. The outer page disables mouse
  drag-pan so desktop rail drags reach the inner rail; wheel scrolling still
  moves the page. Covered landing rails and cards disable on subpages because
  opacity alone does not block hit-testing. Detail's pill bar similarly gates
  its page pan via `pan_hint` / `pan_release` and a short release timer.
- **`ApplyingGuard`** must wrap remote-apply code paths so writes don't echo back to sync.
- **Android packaging is `cargo-apk2`, not `cargo-apk`.** The Java background components (`android/java/`) must be compiled to DEX and the `<service>`/`foregroundServiceType` elements emitted, neither of which the old tool can do; `Cargo.toml` uses `use_aapt2`, `java_sources`, and `has_code = true` in the application metadata, while leaving `extractNativeLibs` to the Android manifest default. An explicit `[[…application.activity]]` is also required (cargo-apk2 generates no implicit activity). The APK launcher icon is configured as `@mipmap/ic_launcher` and packaged from `android/res/`, derived from `assets/logo.png`. The `.#android` shell provides cargo-apk2 from the flake (nixpkgs has no such attr and upstream publishes no binstall artifacts, so it is built with `rustPlatform.buildRustPackage`) and unsets `CPATH` (host include leak breaks the NDK C build).
- **Android builds use `--no-default-features --features android`**; guard desktop-only code with `#[cfg(feature = "desktop")]` or `#[cfg(not(target_os = "android"))]`.
- **Download jobs are local-only**: `downloads:v1` and artifacts are never synced. HTTP resumes require matching `Range`/`ETag`/`Last-Modified`; retained torrent data is protected from playback cache eviction. Each torrent job owns its bundle separately; removing one episode preserves siblings and active playback. Torrent deletion goes through the engine ownership lock, including a worker whose engine was disabled, rather than generic artifact-parent deletion. Transfers are one-at-a-time, so a hung job must not pin the slot: HTTP connects/headers/body-gaps time out (60 s) and a torrent with no progress fails after 10 min; tapping Download again re-arms a `Failed` job in place. A transfer worker carries a done flag; the 250 ms tick reaps one that ended without finalizing (panic/unwind) and the state mutex is poison-tolerant, so a dead worker can never leave every later job stuck in `Queued`. Completed-job validation **canonicalizes** both paths before the root check (Android path aliases), and unreferenced HTTP artifacts under `<data>/downloads/http/` are re-adopted on startup rather than silently dropped (torrent artifacts are not re-adopted: sparse partial files look complete on disk). Deletion (`remove_owned_path`/`remove_owned_dir`) canonicalizes the target the same way — a lexical `starts_with` across the `/data/user/0` vs `/data/data` aliases previously skipped the unlink, clearing the row while leaving the file (and its app-storage footprint) on disk.
- **`Store::try_load` quarantines** unreadable rows/clocks without recursive backups — check `sync:quarantine:*` for evidence. Unreadable identity bytes are not replaced with a new identity.
- **The Android background sync job must open storage before reading settings.** `android_bg::run_headless_sync` sets the files directory and opens storage first, checks both enable flags, and obtains a `BackgroundLease` only when no foreground engine exists. Lifecycle transitions are serialized; foreground attachment takes ownership before job release. `onStopJob` cancels a 120-second-budget `one_shot`, not the foreground worker, and Java finishes at most once. The outcome distinguishes completed/cancelled/timed-out/skipped/failed work; `pass_count` is not a success signal. Device validation remains required.
- The working tree has historically carried uncommitted work on the `iroh`
  branch; check `git status` before assuming a file's committed state.
